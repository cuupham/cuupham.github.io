Game Architecture: Tổ chức một trò chơi để nó còn thay đổi được

Game có nhiều hệ thống chạy đồng thời, vì vậy ranh giới module và data flow quyết định khả năng mở rộng.

Phân tách state

Gameplay state, UI state và rendering state có thể thay đổi với nhịp khác nhau. Tách chúng giúp giảm coupling và làm debugging dễ hơn.

Update loop

Input, simulation, physics và rendering cần thứ tự rõ ràng. Khi timing không được kiểm soát, lỗi chỉ xuất hiện ở một số frame hoặc thiết bị.

Data-driven design

Stats, item, enemy và level configuration có thể đưa ra khỏi code để designer chỉnh sửa. Điều này đặc biệt hữu ích khi content tăng nhanh.

Đừng over-engineer

Kiến trúc nên phản ánh quy mô game. Một prototype nhỏ không cần framework phức tạp; hãy thêm abstraction khi có bằng chứng rằng nó giải quyết một vấn đề thật.
